# TS040HDS02CP-B1620A 屏幕点亮经验总结

记录时间：2026-05-22

本文单独记录本次 TS040HDS02CP-B1620A / TR230S 屏幕点亮过程中的有效经验。该屏幕最容易卡在“不亮”或“背光不亮但液晶有画面”的阶段，后续继续做 LVGL、触摸或正式 UI 前应先复核本文。

## 当前结论

- 屏幕已经确认可以显示白、红、绿、蓝、黑色块；用手电筒照射能看到颜色变化，说明 QSPI 数据链路、TR230S 显存写入和 RGB565 色块基本成立。
- 首版测试走的是 20-pin FPC 的 QSPI / 4SDA，不是 14-pin 排针，也不是普通 4-wire SPI。
- 当前测试固件只做屏幕 QSPI 点亮，不启动 Wi-Fi、USB 业务、触摸或 LVGL，目的是降低首次硬件排查变量。
- 最关键的软件修正是让 SPI 总线初始化稳定返回：使用 `SPI2_HOST`，强制走 GPIO matrix，并避免误写 `spi_bus_config_t` 中和 `data2/data3` 共用 union 的 `quadwp/quadhd` 字段。
- 当前背光由 TR230S 寄存器控制，初始化顺序已经补为：`0x20=0%`、`0x21=100kHz`、`0x29=Display On`、`0x20=100%`。

## 已验证硬件与环境

- 主控：ESP32-S3-DevKitC-1 N8R8，8 MB Flash + 8 MB PSRAM。
- ESP-IDF：6.0.1。
- 屏幕：TS040HDS02CP-B1620A，4.0 inch，720 x 720，TR230S，20-pin FPC。
- 屏幕供电：VCC 为 5 V。
- 逻辑电平：ESP32-S3 GPIO 与屏幕信号均按 3.3 V 逻辑处理，禁止 5 V 直接进入 GPIO。
- 当前测试时钟：`CONFIG_FRIDGE_SCREEN_TEST_PCLK_HZ=10000000`，也就是 10 MHz；稳定后再逐步提高。

## 点亮过程中的关键问题

### 1. WAIT# 正常但仍然 WDT 重启

现象：串口日志显示 `after reset WAIT#=1`，随后卡在 `step: spi bus init start`，复位原因为 `rst:0x8 (TG1WDT_SYS_RST)`。

判断：屏幕复位后的 WAIT# 正常，不是 TR230S 一直忙；问题发生在 `spi_bus_initialize()` 内，还没有向屏幕发送真正的 TR230S 命令。

有效修正：

- 切到 `SPI2_HOST`。
- `bus_conf.flags` 使用 `SPICOMMON_BUSFLAG_QUAD | SPICOMMON_BUSFLAG_GPIO_PINS`。
- 只设置 `data0_io_num`、`data1_io_num`、`data2_io_num`、`data3_io_num`、`sclk_io_num` 等必要字段。
- 不要再把 `quadwp_io_num` / `quadhd_io_num` 单独写成 `GPIO_NUM_NC`，因为在 ESP-IDF 6.x 的结构体里它们和 `data2_io_num` / `data3_io_num` 是同一组 union 字段，误写会覆盖 QSPI D2/D3。
- `max_transfer_sz` 不要设置成整帧 1036800 字节，当前按 50 块传输，设置为 `20736` 字节即可。

### 2. 手电筒照射能看到颜色，但背光不亮

这个现象非常重要：它说明 LCD 像素数据已经写进去了，优先排查背光而不是 QSPI 数据线。

优先检查：

- 屏幕 Pin 2 到 GND 的运行电压是否稳定在 4.5 V 到 5.5 V。
- 外接电源和开发板必须共地。
- 不要把两个 5 V 电源输出硬并联；如果屏幕用外部 5 V，通常只接外部电源的 `5V -> 屏幕 VCC`，`GND -> 屏幕 GND`，再把外部电源 GND 与开发板 GND 相连。
- 如果开发板仍由 USB 供电，不要再把外部 5 V 回灌到开发板 5V 引脚，除非明确确认供电路径、防反灌和开发板允许这种接法。
- 当前固件已补背光相关命令：`0x20` 亮度、`0x21` PWM 频率、`0x29` Display On。

### 3. 长时间运行导致电脑卡死

ESP32 长时间刷屏本身不会直接占用电脑 CPU；电脑变卡更可能来自主机端串口监视器、终端或 Web Serial 长时间接收并渲染大量日志。

已做的软件优化：

- 默认关闭每个色块和每个 QSPI 数据块的循环日志。
- 每个色块默认保持 3000 ms，降低测试循环频率。
- 每 10 轮白/红/绿/蓝/黑循环才打印一次存活日志，默认约 150 秒一条。
- 如需排查点亮失败，可临时打开 `CONFIG_FRIDGE_SCREEN_TEST_VERBOSE_LOG=y` 恢复详细日志。

长稳测试建议：

- 不要长时间开着高输出的 `idf.py monitor`。
- 只需要观察屏幕时，可以烧录后关闭 monitor，让板子独立运行。
- 如果必须抓日志，优先短时间抓取启动阶段和一两轮色块，不要让终端窗口累计数小时输出。
- 若电脑已经卡顿，先关闭 Web Serial、VS Code Serial Monitor、`idf.py monitor` 和残留 Python monitor 进程，再重新插拔开发板。

## 当前固件入口

- 组件：`components/display_test/fridge_display_test.c`
- 开关：`CONFIG_FRIDGE_SCREEN_TEST=y`
- 时钟：`CONFIG_FRIDGE_SCREEN_TEST_PCLK_HZ=10000000`
- 色块保持：`CONFIG_FRIDGE_SCREEN_TEST_COLOR_HOLD_MS=3000`
- 存活日志：`CONFIG_FRIDGE_SCREEN_TEST_REPORT_EVERY_CYCLES=10`
- 详细循环日志：`CONFIG_FRIDGE_SCREEN_TEST_VERBOSE_LOG=n`

## 后续进入正式 UI 前的建议

- 先保持 10 MHz 完成至少 10 到 30 分钟稳定性观察。
- 再按 20 MHz、40 MHz、60 MHz 逐步升频，每档观察屏幕是否花屏、闪屏、白屏、重启或发热异常。
- LVGL 集成时必须使用局部刷新和行缓冲，不要长期整帧 720 x 720 高频刷新。
- 触摸 FT6336U 单独作为第二阶段接入，先做 I2C 扫描，再做触点读取；不要照搬官方例程里的 GT9XXX 触摸代码。
